## Reproduzieren

Voraussetzungen: installierte Projektabhängigkeiten, lokal installiertes Google Chrome, Playwright-FFmpeg im Benutzer-Cache. Falls letzteres fehlt: `npx --no-install playwright install ffmpeg`. Keine neuen Abhängigkeiten in package.json.

1. `npm run check` ausführen. Danach nicht parallel in das vom Server gelesene Build-Verzeichnis bauen.
2. `node scripts/presentation/slides.mjs`, dann `node scripts/presentation/render.mjs`. Der Generator verwendet lokale Screenshots und historische Screenshots über Git-Commit `fc12aad`; im flachen Checkout muss dieser Commit verfügbar sein.
3. Den Ausgabeordner `artifacts/presentation` anlegen, dann `node scripts/presentation/package.mjs`. Das Skript verweigert einen bereits bestehenden Paketordner, damit kein alter und neuer Build vermischt wird. Frühere Ausgaben bei Bedarf unter einem anderen Namen erhalten.
4. Paketordner mit `node artifacts/presentation/studicompass-lokal/server.mjs` starten. `node scripts/presentation/record.mjs --quick`, danach `node scripts/presentation/record.mjs` ausführen.
5. Den Ordner `studicompass-lokal` als ZIP mit gleichnamigem Wurzelordner archivieren und unter `test-results/p6-extracted` entpacken. Die entpackte Kopie mit `node test-results/p6-extracted/studicompass-lokal/server.mjs --port 4174` starten.
6. `node scripts/presentation/verify.mjs` und `node scripts/presentation/verify-media.mjs` ausführen. Prüfbilder und Berichte liegen unter `test-results/p6-*`.

Die Präsentationssitzung und die Artifact-Tool-Laufzeit stehen in dieser Umgebung nicht zur Verfügung. Daher HTML und PDF statt einer als geprüft behaupteten PowerPoint-Datei. Die PDF-Ausgabe entsteht über Chrome mit festem 16:9-Seitenformat. Die Dateien sind für lokale Vorführung und Bearbeitung vorbereitet.
